## 1. Course overview

PM-401 is a 16-week, standards-anchored course in modern project management
for software and data projects. It runs 32 two-hour lectures across seven
units, from *why projects fail* (L01) to a *capstone defense* (L32), with a
16-lab practical stream on the CAMPUS-MEND educational scenario, 105
progressive case studies, and a 25% team capstone defended before a panel.

| Fact | Value | Source |
|---|---|---|
| Programs | BS Computer Science, BS Data Science (Semester 7) | `planning/course-data.yaml` |
| Credits / contact | 3+1 / 64 h (32 × 2 h) | same |
| Standards taught | PMBOK 7 (+ PMBOK 6 vocabulary), ISO 21502, ISO 31000, Scrum Guide 2020, Kanban | `standards` key + syllabus |
| Case studies | 105 (Beginner 20 · Intermediate 25 · Advanced 30 · Expert 30) | `planning/cases/band-*.yaml` |
| Assessment | 8 components, weights sum 100 | `assessment_plan` key |
| Delivery | Lectures + weekly labs + case discussions + capstone milestones | `docs/syllabus/delivery-methodology.md` |

Design principles (from the teaching packages, applied consistently):
constructive alignment (CLO ↔ lecture ↔ assessment), dual CS/DS tracks in
every topic, machine-verified numbers, progressive difficulty, and a hard
separation between student materials (`docs/`, published) and instructor
materials (`instructor/`, never published).

## 6. Lab delivery guide

Sixteen labs, weeks 3–16, all on the shared CAMPUS-MEND educational scenario
(clearly labeled fictional data — `docs/labs/data-pack.md`). Each brief
(`docs/labs/lab-NN-*.md`) has objectives, tools, step-by-step instructions,
student tasks, expected outputs, reflection questions, and a rubric; the
matching key (`instructor/lab-solutions/lab-NN-*-key.md`) has model answers,
common errors, reflection guidance, and prep notes. Every calculation chain
is machine-verified by `tools/check_answers.py` — including the labor roll-up
error the checker caught before release (corrected to 3,225,600 PKR).

Flow that works: brief released in lecture → 2 h in-lab + 1 h refinement →
LMS submission within a week → feedback against the key's rubric. Marking
anchors: `instructor/rubrics/lab-reports.md` (refreshed to the 16-lab design).

## 7. Case study delivery guide

The 105 cases live in `docs/cases/` (student briefs) with keys in
`instructor/answer-keys/cases/`. The directory `docs/cases/index.md`
organizes by difficulty band and tag (band design in
`planning/08-case-study-architecture.md`; metadata in
`planning/case-catalog.yaml`).

- **Beginner CS-01..20** — single-concept; use in-class worked discussions.
- **Intermediate CS-21..45** — 2–3 concepts; pair work with defense.
- **Advanced CS-46..75** — ambiguous, multi-stakeholder; small-group
  deliberation, evaluation criteria graded over answers.
- **Expert CS-76..105** — capstone-feeders and ethics; structured debates or
  written positions.

32 cases are numeric (CPM, float, EVM, EMV, leveling, crashing, Monte Carlo,
FPIF, EVPI, NPV, fairness ratios, portfolio knapsacks) — all recomputed by
`tools/check_cases.py` (380 assertions); each case page names its anchor
lecture. The portfolio (A6, 10%) draws 12 cases across bands, 3 per unit.
Scenario world: MEDSYNC, TELCOCARE, CAMPUSHUB, GRIDSENSE, VOLTPAY, AGROSENSE
— original fiction, no invented citations.

## 8. Instructor preparation checklist (per lecture)

1. Open the teaching package (`instructor/teaching-packages/...`) — read the
   two-hour plan and prep notes the night before.
2. Build/rebuild slides: `python tools/build_slides.py`; open
   `instructor/slides/build/L{nn}.html`; print PDF backup.
3. Check the numeric slides against the package (they are checker-verified;
   any manual edit to a number must be re-verified — see §16).
4. If a quiz opens this lecture: print A/B versions from
   `instructor/exam-bank/` and the marking guide.
5. If a lab runs: skim the brief *and* its key; confirm the data pack CSVs
   are current.
6. If a case anchors: read the student brief and the answer key's
   facilitation notes.
7. Collect exit tickets; skim before the next lecture (they are formative
   and feed the next session's opening).

## 10. Common student misconceptions (consolidated)

Maintained per-lecture in each package's "Common misconceptions" section; the
cross-cutting ones observed during authoring:

1. *Point estimates are the estimate* — the range is the estimate (L10).
2. *Critical = important* — critical means zero float (L11); rollout beats
   rewrite on the path.
3. *Total float = free float* — borrowing from successors breaks them (L11).
4. *Contingency is a slush fund* — it funds identified risks via change
   control (L13/L17).
5. *Quality = inspection* — prevention is the cheap end of the COQ ladder
   (L14).
6. *Heat maps rank risk* — without EMV, low-P/high-I risks get buried (L15).
7. *Monte Carlo rescues bad estimates* — it inherits every O/M/P bias (L16).
8. *The ScrumMaster is the PM* — different accountability structures (L21).
9. *Velocity compares teams* — points are team-local rulers (L21).
10. *More WIP = more progress* — Little's Law says otherwise (L22).
11. *Refuted hypotheses are waste* — they are bought knowledge (L23).
12. *EVM is accounting* — EV is a project definition; define 'earned' in
    verifiable units (L19).
13. *Governance is paperwork* — it lives in WBS rows, budget lines, and gate
    evidence (L27/L28).
14. *AI drafts are shippable* — the signature on the artifact is yours (L31).

  procedures reference the university's own code — the course adds the
