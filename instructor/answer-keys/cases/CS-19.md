# Answer key — CS-19 · Eight data-quality rules for a customer dataset

> **INSTRUCTOR ONLY — not published to the site.**

**Model answer:** Dimensioned rule pipeline

## Reasoning

Structural rules run first (schema, types), then uniqueness (dedupe before completeness, or you repair ghosts), then validity (format/domain checks), then consistency (cross-field), then timeliness (freshness), and accuracy last (needs reference comparison). The blocking rule: duplicate customers — every downstream metric is wrong if identity is wrong, so dedupe failure blocks the batch, while missing tenure (3%) can be flagged and imputed with disclosed assumptions.

## Alternatives and evaluation criteria

- Completeness before uniqueness: defensible when missing rows make dedupe cheaper; here duplicates with different IDs survive completeness checks, so uniqueness first.
## Facilitation

Have students find the rule that can't be automated (accuracy usually needs sampling against ground truth).
