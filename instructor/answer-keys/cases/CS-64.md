# Answer key — CS-64 · Aging WIP and the feature factory smell

> **INSTRUCTOR ONLY — not published to the site.**

**Model answer:** Pull-policy redesign from aging data

## Reasoning

22 WIP at rising cycle time is the textbook symptom: work is started as a stakeholder-management strategy, not a delivery one. Nothing is finished because everything is touched. Policy: WIP limit 8 board-wide, hard; each column gets its own limit; starting item N+1 requires finishing one — the stop rule is 'one new start costs one finished item', which converts finishing into the scarcest resource. The 14 aged items: triage into finish (max 3), park (backlog with dated revisit), kill — decided in one session with stakeholders present; nothing returns to 'in progress' unnamed. Urgent lane: admission = sponsor sign-off + it displaces the lowest-priority WIP item (visible cost), max 1 slot. Aging alarm: any item >25 days highlights; >35 days forces the finish-park-kill decision at the next sync. The next shouter gets the same answer: name what you displace.

## Alternatives and evaluation criteria

- Just raising WIP limits to 'unblock' — the opposite of the diagnosis; the case exists because that reflex already ran for a year.
