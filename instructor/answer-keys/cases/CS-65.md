# Answer key — CS-65 · Sizing the buffers: CCPM for the class project

> **INSTRUCTOR ONLY — not published to the site.**

**Model answer:** CCPM buffer sizing

## Reasoning

Project buffer = 50% × 12 = 6 wk → committed duration 18 wk. Feeding buffer = 50% × 5 = 2.5 wk, inserted where F–G merges into the critical chain before E. The comparison: padded per-task plans protect every task individually, so padding is consumed by ordinary variation and the project still slips (student syndrome, Parkinson's law absorb the buffer invisibly). The aggregated buffer is statistically safer at the same or shorter total duration because independent task variations partially cancel at the chain level. It breaks if private padding survives the cut — the '50% durations' must be genuinely aggressive, or the buffer double-counts the same safety. This is a change-management problem wearing an arithmetic costume.

## Alternatives and evaluation criteria

- Monte Carlo percentile sizing instead of 50% rule: more defensible statistically, needs data the class project lacks; note the connection to CS-22.
**Calculations:** Worked sizing in instructor key; machine-checked.

## Facilitation
