# Answer key — CS-68 · The nine-day silent corruption

> **INSTRUCTOR ONLY — not published to the site.**

**Model answer:** Causal-chain RCA

## Reasoning

Chain: deployment changed a library default → timestamp handling changed → one feature silently corrupted → no invariant asserted on the feature's distribution → training ingested it twice → model degraded subtly → business analyst noticed an odd segment number. Root cause: no distribution invariant on served features — the bug (trigger) was ordinary; the silence was the design failure. Controls: schema-contract test asserting timezone normalization (blocks at deploy); freshness and distribution gates from CS-56 (detect within hours, not days); canary training run with metric deltas before full retrain (contains model damage); analyst-reported anomalies route into the same incident queue as monitor alerts — the human sensor needs a channel, not a compliment. 'Human error' is banned because it ends analysis at the person; the person will be replaced by another person with the same invariants missing.

## Alternatives and evaluation criteria

- Blaming the deploying engineer and moving on: the incident will recur under a different name; RCA discipline exists precisely for this.
## Facilitation

Ask why the second training run also ingested the bad data — the absence of a hold-and-review gate between trainings is the chain's second link.
