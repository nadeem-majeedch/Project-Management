# Answer key — CS-33 · Mapping a 40-person program onto Scrum-of-Scrums

> **INSTRUCTOR ONLY — not published to the site.**

**Model answer:** Bottleneck-first scaling

## Reasoning

Cadences: team standups (existing); SoS twice weekly, 20 minutes, tech leads + platform lead, output = unblocked dependencies; program sync weekly, 45 minutes, cross-team planning adjustments. The platform bottleneck: capacity allocation made explicit — 60% planned roadmap, 30% team requests via a ranked queue reviewed at SoS, 10% incident reserve; a team-as-ticket-queue dies when allocation is implicit. Dependency board: one board, dependencies as first-class cards with requester, provider, need-by date, owner = the provider team's lead. Integration: trunk-based with nightly cross-team integration run and a weekly integration checkpoint — monthly big-bang fails for days because feedback latency compounds errors.

## Alternatives and evaluation criteria

- Adopting SAFe wholesale: defensible for org-alignment politics; the given failure modes are all solvable with the lean structure above.
## Facilitation

Ask what falls off the dependency board first under deadline pressure — that's the design's weak point.
