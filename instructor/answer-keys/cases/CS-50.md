# Answer key — CS-50 · Exclusions as litigation armor

> **INSTRUCTOR ONLY — not published to the site.**

**Model answer:** Definition-first exclusions

## Reasoning

The sentence 'reporting and analytics support' fails because three nouns are undefined. Rewrite: reporting = the six named standard reports with defined filters (listed); analytics = prebuilt cohort dashboards for the registrar role (specified); excluded = ad-hoc query access, custom report development, data export beyond the defined CSV of named fields — each excluded item ends with 'available via change request at standard rates'. Mapping: registrar's cohort trends → in scope (prebuilt dashboard, defined); finance export → excluded, CR path; VC SQL access → excluded, CR path. Exclusions written with a path stay collaborative; exclusions written as a wall invite the dispute they meant to prevent.

## Alternatives and evaluation criteria

- Redefining scope mid-project to include the dashboards: costs a week of re-estimation; honest if the registrar's need is strategic — but that is a CCB decision, not a scope-statement edit.
## Facilitation

Read three student drafts aloud without naming authors; the class votes 'would this settle the dispute?' — most first drafts say 'not included' without saying what WAS included.
