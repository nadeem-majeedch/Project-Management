# Answer key — CS-25 · SLA acceptance criteria for an ML API vendor

> **INSTRUCTOR ONLY — not published to the site.**

**Model answer:** Formula-first SLA + neutral measurement

## Reasoning

Allowed downtime = 43,200 × 0.005 = 216 min. Actual = 43,200 × 0.008 = 345.6 min. Shortfall = 0.3% → three full 0.1% bands → 30% × 400,000 = PKR 120,000 credit. The ambiguity that caused the dispute: 'fast responses' and unclear maintenance windows. Acceptance criteria: availability ≥ 99.5% (vendor dashboard + buyer synthetic probes, disagreement → buyer's data wins); p95 ≤ 300 ms, p99 ≤ 800 ms; error rate ≤ 0.5%; feature freshness ≤ 24 h; P1 support response ≤ 30 min. Percentiles because averages bury the tail.

## Alternatives and evaluation criteria

- Buyer-side-only measurement: simplest, but vendors dispute synthetic probes; dual-source with buyer-priority arbitration is the workable middle.
**Calculations:** Worked penalty computation in instructor key; machine-checked.

## Machine-checked values

Recomputed from the data block by `tools/check_cases.py`.

| Step | Expression | Value |
|---|---|---|
| allowed_downtime_min | `month_minutes * (1 - target_availability)` | 216.0 |
| actual_downtime_min | `month_minutes * (1 - actual_availability)` | 345.6 |
| shortfall_pct | `target_availability - actual_availability` | 0.003 |
| bands | `round(shortfall_pct / 0.001)` | 3 |
| penalty_pkr | `bands * credit_per_band * monthly_fee_pkr` | 120000 |

## Facilitation

Have students find the third 0.1% band explicitly — rounding errors in service credits are a classic dispute.
