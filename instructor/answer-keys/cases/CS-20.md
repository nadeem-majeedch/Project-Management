# Answer key — CS-20 · Twenty risks for a streaming platform

> **INSTRUCTOR ONLY — not published to the site.**

**Model answer:** Category-driven identification with detectability

## Reasoning

Coverage strategy: force at least two risks per category (technical, external, organizational, data, operational, opportunity) to prevent clustering. The naive misses: sensor drift (slow, invisible until accuracy decays), key-person risk disguised as 'bus factor 1' on the pipeline DSL, and the opportunity — vendor API v2 offers cheaper ingestion but only if adopted mid-project. Worst detectability: sensor drift, because monitoring shows 'green' while accuracy silently decays; mitigation is reference-sensor comparison, not alerting.

- None recorded.
## Facilitation

Count category coverage live; the 20-risk constraint exists to force breadth, so enforce it.
