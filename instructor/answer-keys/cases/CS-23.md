# Answer key — CS-23 · Response plans for the top ten risks

> **INSTRUCTOR ONLY — not published to the site.**

**Model answer:** Strategy-fit with secondary-risk accounting

## Reasoning

Sensor drift (high EMV): mitigate via reference-sensor comparison — secondary risk: false alarms erode trust in alerts. Key-engineer exit: mitigate via pairing and documentation; secondary: velocity dip during knowledge transfer. Vendor API change: transfer into the vendor contract (version-support clause) — secondary: higher subscription fee. Office move: accept (low EMV, treatment exceeds exposure) with a dated review. The baseline-flagged ones are sensor mitigation (adds a data task) and pairing (adds labor). The scope-change flag: any 'mitigation' that adds a feature (e.g., a redundant feed) is CCB territory.

## Alternatives and evaluation criteria

- Transferring key-person risk via a retention bonus: defensible; changes it from project risk to HR budget line — name that move explicitly.
## Facilitation

Inspect the accept cases first; students under-accept because accepting feels like doing nothing.
