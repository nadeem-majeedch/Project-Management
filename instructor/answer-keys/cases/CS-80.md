# Answer key — CS-80 · The program rollup that lied

> **INSTRUCTOR ONLY — not published to the site.**

**Model answer:** Bottom-up correction of weighted rollup

## Reasoning

Program: BAC = 6.5M, EV = 4.1M, AC = 4.1M → CPI = 1.000, 'on budget'. Per project: CPI₁ = 0.875 (troubled), CPI₂ = 1.059, CPI₃ = 1.125. Bottom-up EAC = 2,285,714 + 2,833,333 + 1,333,333 = 6,452,381 → program VAC = +47,619. The subtlety: the bottom-up EAC is BETTER than BAC — because P2 and P3's over-performance more than funds P1's overrun — yet the rollup CPI of 1.00 is still misleading: it reads as 'no action needed anywhere', while P1 alone is forecasting a 285,714 overrun that will surface as a funding request at the worst time. Masking mechanism: weighted indices average variances across projects; a program CPI of 1.0 is consistent with any pattern of offsetting project CPIs. Governance fix: program reports show per-project CPI/EAC alongside the rollup — the rollup answers 'are we okay in total', only the decomposition answers 'what needs managing'.
