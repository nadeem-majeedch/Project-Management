# Answer key — CS-75 · Rebalancing the response portfolio

> **INSTRUCTOR ONLY — not published to the site.**

**Model answer:** Exposure-per-rupee rebalancing

## Reasoning

Exposure per rupee: sensor drift 11.1, key engineer 6.4, vendor API 7.0, documentation 2.5, office move 2.5. Fund: sensor drift 90k (top exposure, slow-detecting — detectability argues even harder than the ratio), vendor API 40k (7.0 ratio and a pure transfer — buying certainty). That is 130k; remaining 50k covers key-engineer pairing only partially — this is the strategy change: instead of full pairing (70k), fund pairing only on the two highest-bus-factor components (50k) and mitigate the rest by documentation (the 60k documentation push drops to 0; its residual is absorbed into the pairing scope). Residuals: key-engineer EMV drops to maybe 250k, not zero — named on the register. Office move stays accepted (2.5 ratio, lowest). Secondary risks: partial pairing creates a knowledge-split risk (two components documented, two not) — owned by the tech lead with a named consolidation point at the integration milestone.

## Alternatives and evaluation criteria

- Fund pairing fully and drop documentation: defensible if documentation's 150k EMV overstates reality; the register's estimate quality is the real question — ask how the 150k was derived.
## Facilitation

Ask what the register says about the 150k documentation EMV's provenance — the honest answer is 'someone guessed', which is a lesson about estimate quality, not arithmetic.
