# Answer key — CS-56 · Quality gates for the data pipeline

> **INSTRUCTOR ONLY — not published to the site.**

**Model answer:** Incident-derived gate suite

## Reasoning

Gates: completeness (null rate per column vs 7-day baseline, block at +5pp — the silent null drift), validity (timezone-normalized timestamps asserted in-schema, block — the timezone bug), freshness (max event age, warn at SLA edge, block past it), schema (contract test on column set and types, block), distribution (PSI on key features, warn at 0.1, block at 0.25), volume (row-count vs seasonal expectation, warn). Every block carries an override: on-call data lead may override with reason logged, auto-escalated to the model owner; two overrides of the same gate in a week forces a retrospective. The mapping matters more than the list: each gate exists because an incident paid for it — gates without incident lineage are decoration.

## Alternatives and evaluation criteria

- Blocking on PSI from day one: threshold-setting needs baseline data; start warn-only, promote to block after two weeks of calibration.
## Facilitation

Ask which gate would have caught the nine-day timezone corruption — then ask why nobody wrote it before the incident. That asymmetry is quality management.
