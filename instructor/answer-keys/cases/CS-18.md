# Answer key — CS-18 · Quality metrics for a registration system

> **INSTRUCTOR ONLY — not published to the site.**

**Model answer:** Decision-linked metric selection

## Reasoning

Keep: escaped defects per release (outcomes users feel), defect count by severity trend (in-process signal), user-reported issues per month (post-release truth), code review coverage (process guardrail with a decision: what merge gate applies). Reject: lines of code (measures effort, not quality; rewards verbosity), test pass rate without coverage context (a green suite over 20% coverage says nothing). Targets come from the legacy system's baseline, not industry folklore.

## Alternatives and evaluation criteria

- None recorded.
## Facilitation

Ask who would act differently on each kept metric — if nobody, it's decoration.
