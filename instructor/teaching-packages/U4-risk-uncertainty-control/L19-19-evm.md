# Lecture 19 — Earned Value Management

## Learning objectives

1. Compute PV, EV, AC, and derive CV, SV, CPI, SPI from project data.
2. Compute all four EAC variants, ETC, and TCPI — and state *when each assumption is right*.
3. Diagnose a project's health from EVM patterns, including what indices hide.
4. Design a milestone-based EV rule that resists gaming.

## Required prior knowledge

- L13 cost baseline (the PV time-phasing) and L12 baselining discipline.
- L11 (work-package logic — EV credit needs verifiable completion).

## Teaching notes

EVM is the course's most exam-misused topic: students memorize formulas and
fail the *reading*. Teach the reading first, arithmetic second: **CPI answers
"are we buying progress at the planned rate?", SPI answers "are we moving at
the planned rate?"** — and both inherit the plan's honesty. Garbage baseline,
garbage indices.

The formulas table is 8 rows; the judgment layer is where the session lives:
which EAC variant encodes which *assumption* about the future (the four
variants: CPI holds; planned-rate resumes; both SPI+CPI hold; critical-path
drives), what SPI *cannot* see (it measures schedule position by budget spent,
not by milestones — a project can show SPI 1.0 while missing every
stakeholder-visible milestone), and how milestone-based EV rules fix gaming.

A3 is due today; the midterm (next lecture) blueprint includes a full EVM
item — announce the weighting honestly and point to CS-26 as the practice
case.

## Definitions & concepts

- **PV** — planned value: budgeted cost of work *scheduled* to date.
- **EV** — earned value: budgeted cost of work *actually performed* (credit at
  completion of agreed units — 0/100, 50/50, weighted milestones).
- **AC** — actual cost of work performed.
- **CV = EV − AC** · **SV = EV − PV** (money terms) ·
  **CPI = EV/AC** · **SPI = EV/PV** (indices).
- **BAC** — budget at completion. **EAC variants:**
  1. `EAC = BAC/CPI` — cost inefficiency continues.
  2. `EAC = AC + (BAC − EV)` — the overrun was one-off; plan resumes.
  3. `EAC = AC + (BAC − EV)/(CPI×SPI)` — both inefficiencies continue.
  4. `EAC = AC + bottom-up re-estimate of remaining work` — the plan changed.
- **ETC = EAC − AC** · **TCPI = (BAC − EV)/(BAC − AC)** — the efficiency
  needed on remaining work to land on BAC (or a new EAC denominator).

## Practical examples

**CS:** registration engine at month 4: planned 60% of the 310 h → PV from
the baseline; UI track ahead, integration behind — EV credit per the 50/50
rule on started packages; AC from timesheets (the honest input nobody
over-budgets: if AC is estimated, EVM is fiction).

**DS:** model gate milestone EV — training "80% done" earns nothing under
0/100; the gate's evidence (metrics + fairness + monitoring plan) is the
credit event. EVM's discipline *forces* the model-gate concept from L14/L23
into measurable money terms — a genuinely DS-flavored EVM design.

## Worked example

**Full computation (board), CampusHub month 4:**

Given: BAC = $64,424 (L13's baseline!). Data: PV = $38,400 · EV = $31,900 ·
AC = $36,700.

| Metric | Computation | Value | Reading |
|---|---|---|---|
| CV | 31,900 − 36,700 | **−4,800** | over cost |
| SV | 31,900 − 38,400 | **−6,500** | behind schedule |
| CPI | 31,900/36,700 | **0.87** | $0.87 of value per $1 spent |
| SPI | 31,900/38,400 | **0.83** | moving at 83% of planned rate |
| EAC₁ | 64,424/0.87 | **≈ $74,050** | if inefficiency persists |
| EAC₂ | 36,700 + (64,424 − 31,900) | **$69,224** | if one-off |
| EAC₃ | 36,700 + 32,524/(0.87×0.83) | 36,700 + 45,080 ≈ **$81,780** | if both persist |
| EAC₄ | AC + bottom-up | (case says) ≈ $76,000 | re-plan estimate |
| ETC (from EAC₁) | 74,050 − 36,700 | ≈ $37,350 | remaining spend |
| TCPI (to BAC) | 32,524/27,724 | **1.17** | must run at CPI 1.17 from now |

Diagnosis script (the examinable part): indices say *trouble, moderate, both
dimensions*; EAC₄ > EAC₁ > EAC₂ tells the recovery planner the re-plan is
cheaper than hoping (the one-off assumption looks like denial); TCPI 1.17 is
the credibility test — **ask whether a team running at 0.87 can plausibly run
at 1.17** (usually no → negotiate scope/date, don't promise BAC). What indices
hide here: the migration package is "50% done" for six weeks (EV credit
inflated by a stale 50/50 rule) — fix the EV rule, not just the spending.

## Common misconceptions

| Misconception | Correction |
|---|---|
| "SPI 0.83 = 17% late." | SPI measures budgeted-progress rate, not calendar; only the critical path's schedule reality says "late" — pair EVM with the network (L11). |
| "EAC = BAC/CPI, always." | Each variant encodes an assumption; choosing the wrong one is choosing a fantasy. |
| "Percent-complete is a good EV basis." | Unverifiable percentages are gaming magnets; 0/100, 50/50, or weighted milestones resist inflation. |
| "CPI < 1 means the team is lazy." | CPI measures *plan-vs-actual economics* — the plan may have been sandbagged or heroic; diagnose causes before blaming. |
| "TCPI above 1.1 is fine, we'll hustle." | Sustained efficiency jumps of >10–15% are historically implausible; use TCPI to negotiate reality, not to promise miracles. |

## Classroom activities

1. **CS-26 diagnosis (35 min):** compute the full set (given PV/EV/AC series
   months 1–4), then the written diagnosis: what indices say, what they hide
   (≥ 2 measurement traps planted in the case), recovery recommendation.
2. **EAC variant matching (15 min):** five project situations; teams pick the
   defensible EAC variant and justify the assumption.
3. **EV-rule design sprint (15 min):** design a milestone EV rule for a
   data-project gate that resists "80% done" inflation.

## Discussion questions

1. In CS-26, which EAC would you *report*, and what happens politically if you report EAC₃ when the sponsor budgeted for EAC₂?
2. Why does EVM need an honest AC stream more than an honest estimate — and what behavioral fix enforces it?
3. For an ML project, what is the right EV credit event: "model trained", "gate evidence accepted", or "A/B result confirmed"? Defend against gaming for each.
