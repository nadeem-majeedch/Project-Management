## Description

This course develops the judgment to plan, execute, control, and close
software and data projects. It is anchored in the PMBOK Guide 7th edition's
twelve principles and eight performance domains, retains the widely-used
process vocabulary of the 6th edition, aligns risk practice with
ISO 31000:2018, and operates adaptive delivery through the Scrum Guide 2020
and Kanban. Because the audience is CS and DS students, every technique is
exercised on software and data-project contexts: ML model risk gates, data
quality, cloud cost control, and AI-assisted project tooling.

## Course objectives

By the end of PM-401, a student who has engaged fully with the course will:

- **CO1** — apply quantitative project-management techniques (work breakdown, three-point estimation, CPM/PERT scheduling, earned-value measurement, risk quantification) to realistic software and data projects;
- **CO2** — select and tailor delivery approaches across the predictive–agile–hybrid spectrum, matching method to requirements volatility, regulatory exposure, and team context;
- **CO3** — produce and defend a complete, internally consistent project management plan for a real project context;
- **CO4** — exercise professional, ethical, and responsible-AI judgment in delivery decisions, including data governance and honest stakeholder communication.

## Course learning outcomes (CLOs)

The canonical, fully measurable CLO statements (including the assessment
evidence each implies) live in the [detailed syllabus](detailed-syllabus.md);
condensed:

| CLO | On completion, students can… | Bloom |
|---|---|---|
| CLO1 | **Given** a PMBOK 7 domain map, define and classify the 12 principles, 8 performance domains, and predictive/adaptive/hybrid life-cycle models; **given** a vignette, justify a life-cycle choice with ≥ 3 criteria | Understand |
| CLO2 | **Given** a project brief, construct a 100%-rule WBS with PERT estimates, a CPM network with correct float, and a levelled, time-feasible Gantt baseline | Apply |
| CLO3 | **Given** cost data, develop a bottom-up budget with S-curve and a quality/data-quality plan (≥ 4 metrics, ≥ 8 rules); **given** PV/EV/AC, compute the full EVM set correctly | Apply |
| CLO4 | **Given** a scenario, identify ≥ 18 normalized risks, quantify ≥ 1 via EMV/simulation, propose owned, triggered responses; diagnose project health from EVM data | Analyze |
| CLO5 | **Given** a delivery context, operate Scrum/Kanban/hybrid flow: sprint plans with goal + capacity, WIP limits justified by flow metrics, hypothesis-driven data backlogs, BATNA-based negotiation prep | Apply |
| CLO6 | **Given** a brief, design a complete, internally consistent PM plan and defend its trade-offs in a rubric-scored oral defense, integrating ethics, governance, sustainability, and AI-use norms | Create |

## Teaching approach

- **Case-driven:** 105 progressive cases; at least one anchors every lecture.
- **Constructive alignment:** every CLO is taught (CLO×lecture matrix in the
  planning dossier) and assessed (grading framework); both are published
  openly.
- **Two-hour rhythm:** hook → content block → case → activity → debrief.
- **Capstone spine:** teams form at L08 and carry one project to a week-16
  defense.

## Eligibility & prerequisites

**Eligibility:** enrollment in semester 7 of the BS Computer Science or
BS Data Science program.

**Required preparation:**

- CS students: a completed software engineering course (team-built, tested
  software) and comfort with Git.
- DS students: a completed machine learning or data science project course
  (you have built and evaluated at least one model) and comfort with Git.
- Both: basic statistics (means, distributions, confidence) — used directly
  in estimation and risk weeks.

**Recommended, not required:** databases; any exposure to cloud environments
(helps the cost and Monte Carlo labs).

**Track notes:**

- *DS students:* every PM technique in the course is also exercised in a
  data-project flavor (see the example table in
  [delivery methodology](delivery-methodology.md)); no ML background beyond
  your project course is assumed. The Monte Carlo lab uses basic Python
  (numpy-style random sampling) — a template notebook is provided.
- *CS students:* data/ML cases (TELCOCARE, GRIDSENSE) provide all needed
  domain context; no modeling experience is expected.
