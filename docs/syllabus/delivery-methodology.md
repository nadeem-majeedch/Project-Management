# Delivery Methodology

## Session anatomy (2 hours, every lecture)

| Slot | Segment | Purpose |
|---|---|---|
| 0:00–0:10 | Hook | A failure story, a metric, or a question — activates the session's problem |
| 0:10–0:50 | Content block 1 | Core concepts with a worked example (often hand-computed) |
| 0:50–1:00 | Break | |
| 1:00–1:40 | Content block 2 + anchor case | Apply the concepts to the session's published case brief |
| 1:40–2:00 | Activity debrief + assessment pointer | Defend conclusions; connect to homework/portfolio |

The same shape every week is deliberate: predictability lowers cognitive
load, so effort goes to judgment rather than logistics.

## Method mix

| Method | Share (typical) | Where |
|---|---|---|
| Interactive lecture + worked examples | ~40% | concept blocks |
| Case work in small teams | ~30% | every lecture's anchor case |
| Hands-on labs (tools, artifacts) | ~15% | 12 scheduled labs |
| Discussion / role-play / debate | ~10% | negotiation, ethics, conflicts |
| Assessment in-session | ~5% | quizzes, capstone defense |

## Example threading: every technique in two flavors

Each technique is exercised on **both a software and a data-science
project**:

| Technique | Software example | Data science example |
|---|---|---|
| WBS | Portal module breakdown | Ingestion → features → model → serving pipeline |
| CPM | Integration + UAT sequencing | Data acquisition feeding training milestones |
| Estimation | Story points on user stories | Hypothesis-sized spikes on model experiments |
| Cost | Developer months + licenses | Compute hours, storage, cloud price volatility |
| Quality | Defect density, test coverage | Data-quality rules, model fairness thresholds |
| Risk | Key-person and vendor risks | Data availability risk, model drift, label noise |
| EVM | Work-package EV at month 4 | Milestone-based EV on experiment gates |
| Change control | Scope creep on features | "One more column" dataset churn |
| Closure | Release handover | Model handover to MLOps, monitoring plan |

## How data governance & responsible AI are woven in

Not confined to one lecture: data-quality gates appear in L14, model risk
gates and fairness in L23, privacy/bias ethics in L28, sustainability
(compute footprint) in L29, and AI-assisted PM norms in L31 — mapped
explicitly as knowledge area **KA-DATA-AI** in the
[detailed syllabus](detailed-syllabus.md).

## Team model

- Case teams of 3–4 form in week 1 and rotate per unit — you will work with
  most of the class.
- The capstone team (3–5) is fixed from L08 and carries one project to the
  L32 defense.
- Every capstone team keeps a visible board (physical or digital) — process
  evidence is part of the rubric.

## Accessibility

Students with documented needs: contact the instructor in week 1 so case
teams, lab formats, and timing accommodations can be arranged early. All
published materials meet basic accessibility: real headings, table captions
in text, no color-only information (RAG statuses always carry text labels).
